# Forge 按需仓库检索设计（2026-11-14）

## 当前问题

`Agent._build_messages` 每轮调用 `RepoMap.build`，把最多 4000 token 的静态排序地图放进 system。`RankedRepoMap` 只渲染前 64 个文件；预算耗尽后靠后的候选没有查询入口。地图反复占用上下文，最近路径变化还会触发重新排序。现有 `RepoIndex` 是进程内增量解析缓存，尚无跨进程持久化；Git 忽略和 symlink 安全已有基础。

## 新架构与兼容性

新增 `retrieval` 策略作为默认；`personalized/global/lexical/legacy` 保持原语义供消融。初始 system 仅放预算受控的目录概览、入口和少量任务候选，明确告知检索工具。完整记录在 `RepoIndex`，以 JSON 原子快照持久化于仓库外的本地缓存目录；绝不把快照原文放入提示词。索引失败时仅展示错误状态和安全的极简概览，工具返回明确错误。旧 Python AST 和保守引用图保留。

## 数据结构与索引

每个文件记录路径、语言、大小、SHA256、解析状态、摘要、定义（名称、qualified name、类型、行、签名）、imports/exports 与保守引用；文件图边和全局 PageRank 与索引版本一起保存。缓存键包含仓库真实路径和索引格式版本；每次 refresh 依 Git 文件清单和内容哈希判定变化，仅重解析变化文件。SQLite 暂不引入：第一版继续增量缓存加原子 JSON 快照，避免数据库 schema/锁管理；查询常驻内存，万级文件规模测试后再考虑 SQLite。缓存文件不得进入评测仓库 Git。

## 查询流程与排序

Issue 文本产生初始候选；Agent 使用 `repo_search`、`repo_symbols`、`repo_related_files`、`repo_tree` 和指定路径的 `repo_map` 多轮缩小范围，`file_view` 负责精读。排序融合路径、词法、符号、个性化 PageRank、依赖距离和测试关联；所有权重在配置中声明，并进入评测身份和代码指纹。结果提供逐项分数、总分和截断状态。每题记录查询及重复检测；重复调用返回明确提示，允许改变条件再查。候选多样性通过同目录惩罚，防止单包挤占结果。

## Token 预算

独立配置概览、单次检索、局部地图、文件读取上限；模型上下文、输出和整题 token 仍由现有配置控制。检索工具在输出前计数裁剪并写入是否截断；历史仍由现有 `TokenBudget.trim_history` 裁剪。概览不含完整索引，单次查询上限阻止长列表进入上下文；重复查询不重复输出结果。

## 可观测性

每题记录构建耗时、文件/符号数、缓存命中、查询文本和候选分数、实际读取路径、最终修改路径、首次出现排名及步数、查询 token、重复/截断次数。沿用运行日志及评测逐题 JSON，避免记录密钥。无补丁任务的首次修改排名记为 null。

## 风险与测试

缓存损坏需重建且标记状态；非 Git 忽略近似；动态调用的引用图并不完备；索引读取仍有文件 I/O；模型调用的随机性和 10 题样本很小。先测查询、路径约束、符号、依赖、PageRank、预算、重复、缓存失效和万级合成记录；集成测极简概览找文件；跑全量测试与五轴代码审查。10 题从冻结 30 题按固定散列排序取 10 且尽量覆盖仓库，保存新 manifest；复用旧 30 题结果，Flash 新策略单独跑 10 题并官方 Docker 验证。
